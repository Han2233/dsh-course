01 / LESSON 05

Agent 的连续性，来自可重建的事实

第四课已经让 Agent 读取虚拟文件、修改配置、运行检查。接下来的问题不是再增加一个工具，而是让这段工作在长对话、上下文替换和程序重启后仍然说得清：哪些事实已经发生，哪些事实真正保存，下一次模型会收到哪些内容？

本课沿 Session → Surface → Persistence → Compaction 这条主线研究 dsh。你已有 Agent 基础，因此我们不把“记忆”当成一个笼统容器，而是分别看事件序列、可见消息、请求头、指令来源和持久化边界。学完后，应能解释为什么界面仍显示旧对话，模型却已经改看摘要；为什么保存会话不等于保存进程；以及为什么 Fork 不会复制或回滚工作区。

分析与推断：三层分开，让压缩不必牺牲审计和回看能力，也使“当时模型凭什么做决定”更容易追踪。代价是 UI 不能直接把当前模型数组当作完整聊天记录，恢复端也不能只读取最后一条摘要就声称还原了会话。

02 / LESSON 05

append 成功，首先表示什么

Session.append 接受类型化事件，先把 payload 与 Surface 元数据快照化为无损 JSON，再深度冻结，校验事件局部结构与 Surface 变换。只有候选有效，才进入日志并通知 session/event 观察者。拒绝一次无效追加，不应留下一半的新消息或一段损坏的视图。

事件位置有两个看似相近的概念：SessionSeq 指向已经存在的事件；SessionLogOffset 指向间隙、前缀长度或读取边界，可以等于事件总数。日志有 10 条时，最后一个 seq 是 9，末尾 offset 是 10。把这两种数混用，会让 Fork 边界、恢复游标与替换区间都出现一位偏差。

事件类别是否直接变成模型消息用途
user/message、assistant/message、tool/result满足 Surface 规则时会用户输入、完整回复、工具观察
system/message、developer/message满足规则且内容有效时会系统提示、开发者上下文与工具变化
request/header不会直接成为一条对话记录非历史请求信封
turn/start、step/end、assistant/attempt不会直接成为普通模型消息边界、失败尝试与诊断
compaction/start / summary / end自身不是最终替换消息压缩事务及摘要证据；另有 replacement 消息

这里的“不会直接成为消息”不表示没有作用。request/header 能决定某条工具追加消息引用的是哪份 schema；assistant/attempt 能解释为什么请求次数增加，却没有增加一次成功回答。逐个把原始事件 stringify 后塞进模型，会破坏这种职责区分。

Session 本身是内存对象。同步 append 完成，只说明事件进入当前 Session；持久化观察者可能仍在排队写入。复制 payload 也不是保存到磁盘，深度冻结也不是防止进程崩溃。第四课的“工具已经执行”在这里需要再问一句：对应事实是否已经跨过持久化检查点？

03 / LESSON 05

Surface 是当前视图，日志是历史事实

Surface 维护一组按模型可见顺序排列的事件 seq。普通消息以 surfaceOp: append 加入尾部；替换消息以 { op: replace, startSeq, endSeq } 替换当前 Surface 中的一段连续位置。端点是现存 Surface 节点，范围两端都包含，不能把已经被遮蔽的旧节点继续当作可见端点。

摘要 #5 虽然后写入日志，却占据原来 #1～#3 的逻辑位置。因此当前模型顺序可以是 0、5、4；不能重新按数字排序。原始 #1～#3 没有删除，仍可审计、回放或从一个旧前缀另开分支。

deriveMessages() 遍历当前 Surface 节点，再按事件类型派生消息；它增量缓存普通尾部增长，在 replacement 或内容投影代际变化时重建缓存。返回数组是新的快照，其中共享的消息对象已冻结。这个设计既避免每次完全重算，也避免调用者无意改坏日志。

人类对话另有规则。源码的 isAppendSurfaceEvent 明确将 append-origin 消息作为原始对话材料，replacement 副本保留给模型视图。第五课左侧因此始终显示原对话，右侧模型视图则在修剪、压缩后变化。摘要不冒充你亲自发送的新消息。

还有不改变节点位置、只改变内容的插件投影，例如图片卸载。插件要注册纯解释器，对应持久事件才能在恢复时重放；缺失解释器会拒绝追加或恢复。不是把当前内存消息改掉就算完成了“可恢复压缩”。

04 / LESSON 05

恢复一组消息，还不足以重建一次请求

模型请求还包括提供方、模型配置、工具 schema 等非历史字段。dsh 使用 request/header 保存这部分规范快照，而系统提示是 system/message，不是可以任意塞回 header.system 的第二份来源。消息视图与请求头共同说明当时的输入。

请求头 reason 区分 initial、resume、change 与 series。工具和配置不变的同一系列请求可以继承当前 header；Surface 替换或消息内容投影会形成新的消息系列，即使信封值没变，也要留下相应记录。显式参数与 adapterDefaults 还要区分，不能把后来提供方的默认值倒灌成旧请求的事实。

工具声明变化尤其需要历史身份。developer/message 中的 tool-addition 名称通过 headerSeq 引用更早的 request/header，应该找到那一份完整 schema；最新注册表里同名工具的定义不能替代旧定义。第四课工具卸载或覆盖的知识，在这里变成可重建性问题。

工作台只显示简化的消息快照与工具名称，并标明不是原始 dsh 格式。源码阅读时要把这个演示与生产请求投影区分：真实实现还处理提供方协议、延迟工具定义、模型能力及完整工具历史。

05 / LESSON 05

flush 是边界，不能用“已经显示”代替

SessionStore.flush 会等待参与 session/flush 的全部监听者收敛，再报告失败；返回 boolean 说明有没有持久化监听者参与。没有后端时，内存 Session 依然可以运行，但不能因为调用过 flush 就声称数据已落盘。

session-checkpoint-policy 把持久化与语义边界相连：模型流真正构建前先 flush；顶层工具调用进入执行体前先保存对应调用记录；下个请求前检查前一步的响应和结果。嵌套工具复用外层已持久化调用。检查点失败时，后续模型派发或工具体不会照常执行。

这能缩小“副作用发生了却没有调用证据”的窗口，但不构成所有外部服务与本地日志的分布式事务。工具完成后、结果尚未保存时进程崩溃，恢复仍可能只能判断结果未知。正确做法是核查环境，而不是凭一次重试补出想象中的成功。

JSONL 后端默认采用带校验的 Zstandard 帧；compression: none 才是裸换行文本。物理编码压缩减少存储字节，和减少模型上下文的摘要压缩是两件事。后端按会话保存文件与格式代际，第一次物化、追加批次、格式迁移都有自己的校验和发布规则。

后续批次追加并 sync；捕获到写入或同步失败时尝试回退到之前长度，避免重试批次制造重复 seq。恢复时可以丢弃不完整的最后裸行，或从损坏尾帧中保留已完整解码的记录；完整已提交帧的校验、结构或解压错误则应被当成损坏，不是无限向前截断直到“能读”。

06 / LESSON 05

恢复会话不会让时间倒流

恢复端必须验证序列连续性、消息结构、替换关系和所需投影解释器。fromRestore 接受独立拥有或已经深度冻结的 seed，按约定接管对象，避免把共享可变对象当成历史事实。它不是把任何 JSON 数组赋值给 messages 的捷径。

恢复还要处理生命周期边界。中断的 turn 或 step、已经声明但没有完整结果的工具调用，需要保守的收尾记录，不能把调用结果未知解释成“从未执行”。底层构造、恢复流程与工具历史修复各有职责；不要仅凭调用 fromRestore 就假设运行中的所有任务会自动重新启动。

恢复了什么没有自动恢复什么
已持久事件及其可见消息投影进程内的 promise、线程和活跃网络连接
会话身份、历史请求事实过去某时刻的外部文件系统
调用与结果的记录或保守缺失信息没有证据的工具成功状态
日志中的指令和摘要内容永久不变的工作目录与工具实现

工作台的保存点是页面内存里的序列化字符串；恢复按钮模拟丢弃未保存尾部，再从保存点派生会话。这有意放慢了写回机制，让你能看见差别。真实部署的自动检查点会在请求和工具边界保存，不能从本实验推导真实 dsh 默认会让完整工具轮次长期处于未保存状态。

恢复后的虚拟文件依旧是 timeout: 30，因为存储实验只保存会话日志，不保存文件快照。Git、文件备份和事务性环境是另外的机制。浏览器刷新会清空本课全部状态；“教学存储”不是 localStorage，也不冒充真正的磁盘持久化。

07 / LESSON 05

Fork 复制确定前缀，不复制正在运行的世界

SessionStore.fork 从一个活跃源会话的精确前缀创建子会话，boundary 是包含在副本内的最后事件 seq，默认是当前最后事件。它可以从一个较早边界分叉，而不是只能复制当前可见 Surface。即使日志中部分内容已被压缩遮蔽，过去的事件仍属于可选前缀。

buildForkSeed 复制包含边界的前缀，加入 inherited 的 session/end-seed，然后为开放尾部补 forked 收尾。inheritedEventCount 只计真正复制的前缀，标记与合成收尾属于子会话自己的事件。关闭过的步骤与轮次保留原样，不会借分叉之名把所有历史缺失结果随意补好。

这保证了子会话可以从一个自洽边界继续，而不意味着父 Agent 的执行栈、在途工具、审批或后台任务也克隆了一份。下一课讲的子 Agent 编排还需要自己的运行时与通信规则，不能把 Session Fork 与 spawn 一个执行者等同。

本课只在已完成轮次的边界分叉，不模拟在途调用收尾。分叉后追加消息，再切回父会话，观察父日志没有变长；虚拟文件仍共享。这样能把“对话路线分叉”与“环境隔离”明确分开。

08 / LESSON 05

指令与 Skills 也必须有可追踪的进入时机

AGENTS.md 和 Skills 常被统称为“上下文”，但来源和进入时机并不相同。agent-instructions 在首个请求前建立基线指令上下文；成功的文件工具触达路径后，会考虑嵌套、修改和移除的指令，再在后续边界把变化加入输入。

源码不仅监听一个文件名，还要处理执行祖先关系、工具成功与否、取消信号和 step/end。异步扫描如果在被取消的执行之后仍随意修改 Inbox，就可能把不该进入的材料带到下一轮。这里的排队与提交边界和第三课的消息接纳是相连的。

材料初始呈现正文如何进入
项目指令基线与作用域相关的指令内容预步骤组合，成功文件触达后的变化再排队
Skill 目录名称、描述等可选能力摘要目录存在不代表全部正文已加载
skill 工具模型可调用的加载入口按调用者作用域重新检查可用性，读取正文
显式 /skill-name直接用户消息的调用形式符合用户可调用规则时，在 pre-step 注入正文

tool-skill 会在 list 和 get 两处检查技能是否仍可调用。模型目录中的名字不是永远有效的承诺，和第四课的工具可见性类似。显式用户调用与模型自主调用也不是同一开关：某些技能禁止模型自主调用，但仍允许用户显式调用；不可简单把一个“禁用模型调用”解释为所有入口都不存在。

技能正文可以作为工具结果进入记录，显式调用则通过有来源标记的注入消息进入。它们不是偷偷写入不可见的永久记忆。长对话时，摘要还应保留必要约束与下一步；但“原文保存在日志”不保证每一次模型请求都重新携带技能全文。

教学工作台不扫描你电脑上的 AGENTS.md 或 SKILL.md，这一节用来源矩阵和真实源码解释。本课页内不会因讲到这些文件就执行任何技能内容。

09 / LESSON 05

先修剪长输出，再决定是否需要摘要

tool-result-pruner 不请求模型。它测量当前工具结果中文字的 Unicode code point 数，超过配置阈值时保留开头和结尾，中间插入标记，非文本块维持相对位置。code point 不是 token，也不完全等于人眼看到的字形；这种计量避免切开 UTF-16 代理对，但组合字形仍有边界问题。

实现先获取稳定的当前 Surface 候选集合，为每次替换追加 compaction/prune 的计量记录，再追加同 callId 的 tool/result replacement，引用被替换节点。日志中的旧结果原样存在；重放这些事件可以得到同一个修剪后视图。

默认 compaction-basic 的压力路径会先判断触发条件，符合条件后再调用可选 pruner 并重新计量。若修剪已使上下文低于阈值，就可以跳过摘要请求。因此“超过工具输出阈值”不等于任意时刻都会自动修剪；集成调用的触发时机同样重要。

本课提供手动修剪按钮，为了单独观察这一机制，不模拟完整自动调度。教学阈值故意很小，以便一屏看出效果。它保留工具调用与结果身份，却可能省略重要错误细节；需要分析被省略部分时，应回到原日志或重新取得精确材料。

10 / LESSON 05

摘要压缩是一段有失败边界的日志事务

摘要压缩（compaction）选择较旧的一段上下文，保留近期尾部，并用新的 checkpoint 消息遮蔽所选范围。第一个 system/message 节点受到保护，工具调用与结果不能在选区边缘被拆开。近期保留量与压力阈值由路由和计量服务共同决定，不是简单保留“最后十条”。

默认策略同时考虑上下文窗口 W、请求输出预留 O 和额外余量 B：触发值按 floor(min(W × thresholdRatio, W − O − B)) 计算。若小窗口无法容纳这些预留，配置应明确调整；盲目套用大窗口默认值会得到无效空间。没有可安全压缩的完整单元时，不能靠拆断工具配对强行腾位置。

BasicCompaction 的默认 summarizer 重放对话的系统头、工具和被选中消息，在最后追加摘要指令，尽量保持可复用的请求前缀。生成的是结构化 checkpoint，要求记录意图、文件、错误、待办、当前工作和下一步。这里只保留合适的摘要文本；模型“被要求保留全部关键事实”不构成无损压缩保证。

生成摘要期间世界可能改变。自动压缩检查整份 Surface 的稳定性；手动 idle 压缩关注所选 span，可以允许选区外仅追加上下文。摘要若已经过期、未缩小、被取消或返回不支持的内容，就不能照常覆盖旧上下文。失败通常也要尝试写 compaction/end；关闭失败会留下可检测的未闭合事务。

更细的取舍是：修剪或图片卸载可能已经先落入持久记录。后续摘要失败，不等于整个过程从未改变模型输入。恢复逻辑必须检查是否已经有有效的新投影，而不是凭异常把所有变化粗暴抹掉。手动压缩结束后的 flush 也可能单独失败，需要分别描述“内存替换已发生”和“持久检查点未成功”。

工作台把候选生成与提交拆成两次点击，可选择模拟摘要失败或取消。摘要由固定中文模板构造，界面中的长度是字符计量，不是上游 token-meter 的路由定价；不调用真实摘要模型，不模拟自动溢出重试或图片卸载。

在同一台 Agent 里比较三份视图

一条贯穿保存、压缩与分叉的证据链
发送初始任务后，虚拟文件从 timeout: 0 改成 30，工具结果进入事件日志。完整工具框架沿用第四课，但本课默认准入允许、自动运行前置步骤，把操作注意力留给会话层。
保存时复制当前分支日志到教学存储。随后增加两条未保存消息，日志变长、保存点不动。恢复时回到已存前缀，再增加生命周期标记，未保存消息消失。数字不必恰好等于保存条数，因为新生命周期可以合法追加自己的事件。
长诊断经修剪后，当前 Surface 指向新的同 callId 结果；原来那条长输出还在日志与对话。准备摘要时先记录 start，模型可见内容尚未替换。提交成功后增加 summary、replacement 和 end，新模型视图变成系统头、摘要与近期尾部。
Fork 把这段含替换决策的日志前缀复制到子会话，所以子会话重放时同样得到压缩后的 Surface。在子会话增加一条消息，父会话不变；切回父会话即可验证。两者面对的虚拟文件仍是同一个环境，没有“回到 timeout 为 0 的磁盘”。
故障情境也值得对照：先勾选模拟摘要失败，再准备与提交。你会看到 start / end 事件增加，却没有 replacement；已有修剪继续有效。取消候选也是同样的原则：结束事务，不凭空恢复早已被其他持久决定替换的视图。

13 / LESSON 05
长对话管理的收益与代价
事件溯源、缓存投影、快照和摘要并不是 dsh 独有的发明。本课值得学习的是它们怎样围绕 Agent 的请求边界和工具副作用协作：消息变换有来源，持久化有检查点，压缩有事务，Fork 有准确前缀。
方案（课程内自建对照）优势需要接受的代价
直接维护 messages 数组少量代码，适合短暂一次性任务难区分原始历史与修改后的模型视图
事件日志 + Surface替换有据可查，支持重放与分叉更多类型、位置、投影与迁移契约
确定性结果修剪不消耗摘要模型请求，可重放中间内容可能丢失，不能理解语义重要性
模型摘要 checkpoint可归纳跨多轮意图、状态与待办需要额外请求，存在遗漏、成本与过期问题
物理 Zstd 编码降低日志存储体积不降低模型上下文，需对应解码与损坏处理
排查长任务“忘事”时，先判断材料是否从未进入日志、是否未保存、是否被 Surface 遮蔽，还是摘要没有保留关键细节。排查恢复后的错误时，再看工具状态与外部环境是否已经变化。不要把所有问题归咎于模型记忆长度。
工程上也要承认保证的边界：可重建的请求不等于再次请求必然得到同一个回答；原日志还在不等于下一次请求会自动读全；保存已确认不等于第三方副作用与日志完全原子。清楚这些边界，才知道需要补哪一层能力。
