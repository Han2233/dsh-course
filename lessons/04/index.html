01 / LESSON 04

从“模型想做什么”，走到“环境实际发生什么”

第三课结束时，模型已经能提交完整的工具调用，驱动器也会把结果交给下一步。缺口在调用与结果之间：谁决定工具能不能被看见、该不该执行、在哪个环境执行，以及结果怎样回到模型？第四课沿这条链读源码。

本课重点是 ToolRuntime、工具定义和能力后端。读完后，你应能追踪一个 edit 调用经过的策略与执行层，区分 schema、权限与环境限制，解释为什么审批同意后仍可能失败，以及为什么结果被拦截不等于修改被撤销。第一课的组合决定加载哪些层，第二课的作用域决定它们对谁有效，第三课的循环负责调用和接回结果。

把工具写成一个函数，然后直接执行，适合最小原型。长期运行的 Agent 还需要处理插件卸载、作用域收窄、人在审批时取消、并发读写冲突、远程连接失效等情况。分析与推断：dsh 把这些责任分层，可以让同一个工具定义接到不同环境，并让策略跨多种工具复用；代价是排查一次失败需要知道它停在哪一层。

02 / LESSON 04

一份工具定义，有三种不同的读者

defineTool 让工具作者声明输入参数、规范返回值（canonical value）、执行体及渲染方式。输入既服务于 TypeScript 类型推导，也生成运行时 JSON Schema 校验。模型只得到 name、description、parameters 等白名单字段，得不到 execute 函数；schema 是一份可调用契约，不会自己完成操作。

要特别留意校验位置：注册表先建立独立的 JSON 参数快照并冻结；defineTool 的 execute 包装再校验参数，通过后才进入作者的函数。不要把“参数已被冻结”和“语义校验已通过”混为一谈。直接构造 ToolDefinition 的桥接器需要遵守自己的输入契约，例如 MCP 桥接会把参数交给远端并校验返回协议。

模型读取

name: edit
parameters:
  file_path
  old_string
  new_string

说明工具怎么调用，不包含实现与批准结果。

output.schema

拥有函数、结果类型与并发分类器。

历史与界面读取

表达发生了什么；不能据此完整复原执行端所有对象。

三张卡是同一工具的三个投影，字段为节选；规范 value 可供程序调用使用，而 Session 保留渲染内容和可选展示元数据。

作用域决定可见性。全局注册是起点，近层同名定义覆盖远层；继承的能力经过链上限制的交集，当前作用域自己注册的工具保留。这个“自己的注册”例外服务于子 Agent 的回答工具等场景，不能简单理解为一个全局 allowlist。get(name, scope) 与 schemas(scope) 都要带着调用者的视角理解。

可见性也不等于永久有效。模型请求里冻结的 schema 可能来自之前的时刻；真正分发时会重新解析当前作用域中的定义。插件在此期间被卸载，原调用仍可能得到 unknown tool。第二课的生命周期因此直接影响第三课之后的执行。

03 / LESSON 04

把一次调用拆成可以定位的阶段

执行流水线（execution pipeline）既承担准入，也承担结果整形。把所有步骤称作“中间件”容易掩盖权限差异：有的阶段能阻止执行，有的只能影响已经得到的结果，有的只能旁观。

阶段持有什么可以改变什么 / 不能保证什么
调用快照name、callId、agent、冻结的 arguments隔离调用参数；不允许 pre-execute 随意重写参数，让日志和真正执行的内容失配
tools/pre-execute作用域中的调用事实waterfall 返回 allow / deny / ask；ask 进入审批服务
单调 guard最终允许决定之后的调用返回理由即可拒绝；其他 guard 不能把拒绝改成允许
tools/execute around-dispatch 包装与 execute可包装执行与信号；原调用者取消信号会重新融合
projectContent / post-execute规范结果及执行端准备的显示内容替换内容、替换规范值或 block；不能据此推断副作用已撤销
finalizeContent / tools/result收敛后的结果定义方做最后内容变换，再通知只读观察者；观察者失败不重写结局

普通工具抛错会变成工具错误结果，模型可以在下一步读取并处理。流水线自身失败也会收敛成结果，但可能走提前终结路径：上表是正常调用的主线，不承诺每种取消、无效输入或扩展错误都会经过全部阶段。例如在准备前就取消的调用不会真的进入执行体。

post-execute 可以返回 accept 并替换 content，也可替换 value，由输出契约重新校验和渲染；两者不能同时替换。返回 block 则把外层调用标记为错误，只保留该拦截决定显式附带的额外上下文。工具自己延迟附带的上下文并非总会送给模型。

假设 read 返回一份配置，后置策略把模型显示内容替换成“已隐藏”。如果只是替换 content，程序调用者仍可能持有原 value。需要阻断数据访问时，要在执行前阻止，或使用合法的值替换 / 阻断机制，不能把界面脱敏当成完整的数据边界。这一结论来自返回值分流方式，不是对所有脱敏产品的泛化判断。

04 / LESSON 04

审批、守卫和沙箱分别回答什么

ask 表示此调用需要经审批渠道作出决定。serviceAsk 临时获取 approval 服务；没有服务、没有可路由的 agent 或渠道不可用时，都不会默认放行。allowed-once 只让这次调用继续；rejected、cancelled、unavailable 的原因被区分，便于解释阻塞发生在哪里。

随后才运行单调守卫（monotonic guard）。你可以把审批理解为签署本次工作单，guard 理解为该工作仍须满足的强制条件。签字不会删除“禁止修改受保护文件”这条规则。这个类比只对应软件准入，不代表 dsh 替你判断业务合规性。

层所回答的问题批准后仍可能发生什么
可见性 / restrict该 Agent 能获得哪个工具？工具随后卸载或被限制
pre-execute / approval是否准许这次调用继续？guard 否决、执行错误
guard必须满足的规则是否通过？能力后端仍可能拒绝
沙箱 / 能力服务实际环境允许哪些资源访问？路径越界、只读限制、隔离能力不可用

工具准入审批和沙箱升级审批也要分开。文件 edit 的 FsSandboxController 在执行前解析每次操作的沙箱策略；显式请求更宽的访问，走 approveEscalation。它不是“工具审批点过一次，就获得永久无限权限”。第四课工作台只模拟 pre-execute 的一次性审批，不实现宿主权限升级。

当前 fs-sandbox 是可信文件服务对模型提供路径的策略围栏：read-only 拒绝写入，workspace-write 检查规范化后的目标是否位于允许根下，danger-full-access 不加该写入围栏。读取透传。源码明确说明，这不等同于运行任意不可信代码的内核安全边界；祖先符号链接在检查与系统调用间变化仍有残余竞态。

因此不能用页面上的一个“沙箱已开启”徽章证明全部隔离属性。实际部署还要看提供方、平台、策略模式和执行时证据。这里讲的是固定源码快照的层次；浏览器工作台没有系统调用，也不会宣称自己建立了操作系统沙箱。

05 / LESSON 04

先读后改，保护的是哪一个版本

tool-fs 拥有 read / write / edit 的语义、格式与观察事件，具体存储由 ctx.fs 实现。edit 使用字面替换：file_path 不能空、old_string 不能空、old_string 与 new_string 不能相同；默认要求唯一匹配，replace_all 才替换所有匹配。它不是任意代码求值，也不是凭自然语言自动生成文件。

“先读再改”来自可选的 fs-observation-policy，并非 edit 函数无条件保证的规则。该插件用 Session 所有者和 targetKey 记录存在 / 不存在及版本，收到 edit-intent 时返回观察到的版本。没有它时，工具可使用后端无版本条件的调用。不能看见一个 read 提示词，就假设整个部署必然启用了冲突保护。

版本检查必须跟实际修改绑定在后端的原子修改机制里。先 stat，再过一段时间 write，中间仍可能被别的写入打断。dsh 的工具端把 guard 交给 editText，而不是自己先 stat 制造一份似是而非的安全依据。

观察状态write-intentedit-intent
未见过 / 无 ownercreateIfAbsent，不能直接覆盖已有文件FS_NOT_OBSERVED
确认不存在createIfAbsentFS_NOT_FOUND
确认存在，记录版本 vreplaceIfVersion(v)传递 version: v 给后端

成功修改会发出新的 fs/observed，用结果版本更新观察依据。一个策略插件负责记忆，一个能力服务负责原子执行，职责组合才构成完整保护。若 HMR 卸载观察插件，它会清理记录；不要假定曾经读过的事实可以跨任意插件重载自动继承。

工作台允许在读完之后点击“模拟外部修改”。你会看到虚拟文件版本增加，观察版本不变；继续 edit 会返回冲突，文件不会被旧依据覆盖。该实验用整数版本和同步内存替换表达原理，省略了路径别名、文件锁、编码、大文件与真实原子发布。

06 / LESSON 04

执行成功、检查通过和任务结束不是一回事

bash 工具把命令交给 ctx.shell；不同执行器决定具体进程和隔离行为。每次普通 bash 调用使用新 shell，变量、函数和 cd 不会自然保留到下一次。相对 workdir 根据会话工作目录解析，实际请求还要与沙箱策略的工作区身份一致。

一个检查命令可以成功启动、正常退出，并返回 exit code 1。这表示检查没通过，不一定是工具框架异常。dsh 将 stdout、stderr、退出标记等交给模型判断。相反，工具不存在、准入拒绝或参数无效属于另一层错误。工作台的 demo.check 只计算虚拟配置里的 timeout 是否大于零，输出 exitCode，不调用操作系统 Shell。

调用层isError = false检查器确实运行并返回了值
检查层exitCode = 1配置不满足检查条件
任务层仍需修复不能从“工具正常返回”推导任务成功

长命令还引出另一种边界。组合 jobs 服务且允许提升时，前台命令从开始就成为受管作业，超出前台等待时限可返回同一个 job id；之后由 job_output / job_kill 获取结果与停止。缺少作业注册、拒绝注册或配置不允许提升，会回到执行器的超时结束路径。超出等待时间不自动等于进程已终止。

还有工具级的 timeoutMs：单独写在定义上只是声明，需 timeout-policy 包装执行才落实。它通过 AbortSignal 协作取消并等待执行体收敛，没有用 Promise.race 把还在写文件的 promise 扔到后台。忽略取消信号的工具也不会因为这个字段而获得强制隔离；进程级终止仍由实际执行器负责。

07 / LESSON 04

并发的是执行体，结果仍按模型顺序提交

工具可以声明 isConcurrencySafe(args)。只有精确返回 true 才进入并行分类；未声明、抛错或返回其他值都视为 exclusive。这个分类由解析到的定义拥有，不是任意事件监听者临时放行。只读操作通常适合并发，但源码不会仅凭名字含 read 就认定安全。

Agent Loop 使用有界滚动池，exclusive 调用形成屏障。计划中的调用在开始前还会重新分类；插件变化可使原本安全的调用成为独占。pre-execute、结果最终化以及上下文提交维持模型顺序，只有实际分发体可以重叠。

取消会停止补充未开始调用，等待已启动调用结束，再为跳过的调用补合成结果，保持模型调用与结果配对。调度器内部失败同样先收敛已启动任务，然后交由上层记录保守恢复结果。取消并不是把已经发生的网络请求或文件修改穿越时间删除。

取舍：有序提交利于历史解释与策略确定性，但慢的前序调用可能挡住已经完成的后序结果。并行池改善执行吞吐，不保证用户立即看见最快返回的那一项。本课工作台主案例有读→改→查依赖，故意顺序执行；上面的时间轴单独解释独立调用的调度。

08 / LESSON 04

MCP 连接的是另一端的能力

MCP 客户端把远端工具包装进同一个注册表。模型看到类似 mcp__github__create_issue 的公共名，远端 tools/call 收到的是原始工具名。命名空间来自本地配置的 serverName，不能由远端自报名称随意改变。多个服务的 search 因此能共存。

桥接器负责发现、名称转换、注册替换、调用和返回内容投影。工具列表更新有代际边界：准备失败保留旧集合，注册冲突不应留下新旧混杂的部分集合。连接暂时中断时，旧工具可能仍列在列表中，但实际调用失败；可见不代表在线，更不代表调用的远程副作用处于本机沙箱中。

远端 isError 会转换成失败，不能伪装成功。canonical MCP value 与准备好的 text / image 投影分别保留，projectContent 在后置策略前装入内容，让后置处理看见真实返回内容。图片是否可用还取决于模型能力和附件服务；不能在缺少条件时静默宣称模型已经看见图片。

本课不要求配置外部服务器，也没有把远端服务搬进浏览器。它要帮助你判断新增一个能力时，何时直接写 dsh 工具、何时复用 MCP 接口，以及排查应在注册表、连接层还是服务器端进行。

09 / LESSON 04

Native 与 PTC 改变的是编排和呈现方式

Native 模式向模型呈现各个工具 schema；模型给出一个或一批调用，结果进入下一步。PTC（Programmatic Tool Calling，程序化工具调用）模式把直接入口收束为 run_code，再给模型生成可调用能力的 SDK。程序里的 tools.name(args) 仍回到注册表子分发，仍经过作用域、策略、审批、守卫和结果处理。

所以 run_code 不是一个绕过工具权限的万能函数。纯 ptc 模式下，模型直接调用被收束的终端工具会被拒绝，并提示从 run_code 内调用；both 则提供两种呈现方式。模式属于 Agent，不能想当然地把某个工具单独设为 native、另一个设为 ptc。运行时语言也必须有对应 SDK 渲染器。

这是两种教学编排的对照，不执行页面中的代码。函数名为本课 demo 工具。调用次数的差异只对应这个固定案例，不是普遍性能承诺。
当多次操作和筛选能在程序内完成，模型不必每次读回完整中间结果。只有打印或返回的内容进入外层输出；成功子调用中的图片还有额外上下文路径。内部调度记录可供审计，不代表会自动逐项进入模型消息。
与此同时，程序得到的是类型化规范 value；工具失败以 ToolCallError 拒绝，可以 try/catch。对独立调用使用 Promise.all 不代表所有工具都会同时执行，注册表的独占屏障仍有效。依赖前一步结果的写入必须 await，不能靠提交顺序假装数据依赖已满足。
Node PTC 后端在新的受管、受限 Node 进程里执行，每次运行有新状态，受输出、消息和运行时间等限制。它不是跨调用隐式保存变量的 REPL。减少模型往返可能节省上下文，却增加代码组织、隐藏中间值和调试成本；SDK 本身也占提示词空间，不能把 PTC 概括为必然减少 token。

11 / LESSON 04
同一份配置，三种证据要一起读
正常路径起始文件为 timeout: 0。第一次请求让脚本 Agent 选择 demo.read；执行端读取真实的页面内存并记住版本 v1，返回内容被写入历史。第二次请求带着读结果选择 demo.edit；你批准后通过守卫与版本判断，文件更新到 v2。第三次请求选择 demo.check，它读取更新后的文件计算 exitCode。第四次请求形成总结。
这里的“真实”仅限浏览器状态变更，不表示模型智能真实运行。固定脚本只会把旧文本中的 0 改为 30；再次执行同样任务时，若已经没有旧文本，会报没有匹配。这是帮助观察错误边界的脚本限制，不能宣传为会自动规划修复方案的 Agent。
观察位置代表的证据不能单独得出的结论
文件实际内容 / 版本虚拟环境现在是什么样模型已经收到最新内容
执行端候选结果本次工具返回了什么后置策略最终一定接受
请求显微镜 / 模型历史当前或下一请求实际携带什么环境从此不再变化
在检查器先看候选结果，再按“处理执行后结果”，最后按“提交最终工具结果”，可以把这三个时间点分开。若在修改执行后、结果提交前取消，虚拟文件保留改动，历史记录取消后的结果；已完成的同步内存修改不会被撤销。真实系统还需等待在途调用收敛，本页没有并发进程，故省略这段等待。
第四课的成果是一台有可观察副作用的教学 Agent：能从声明走到执行，再把结果带回下一次请求。第五课将研究这些历史怎么保存、恢复、裁剪和压缩，让任务跨越更长的时间，而不是简单扩展一张 messages 数组。

12 / LESSON 04
扩展工具之前，先确定要接入哪一层
工具体系的特色是组合已有机制：类型化定义、作用域注册、可插拔策略、有序调度与多种后端，没有必要把其中每个概念都称为首创。其收益是在 Native、PTC 和桥接能力之间复用执行约束；代价是开发者要尊重值、内容、执行和持久事实的边界。
你要改变的行为优先入口典型误区
增加一种新能力defineTool + ctx.tools.register把执行代码塞进提示词
限制某个 Agent 继承的能力tools.restrict / 作用域组合只在 UI 隐藏按钮
增加不可被后续监听覆盖的否决tools.guard用普通 waterfall 监听充当所有强制边界
需要人决定一次调用pre-execute 的 ask 与 approval 服务无渠道时默认放行
换文件或命令实际运行位置ctx.fs / ctx.shell 的提供方只改工具描述就宣称有沙箱
组织一段工具调用程序PTC runtime + 呈现模式假设中间值自动进入模型历史
改变最终展示内容project / post / finalize 的合适阶段误以为替换文本能撤销副作用
小型脚本如果没有插件热更新、人工审批与长任务恢复，可以采用更少的层。若确实需要这些能力，简化的重点应是选择必要组合，而不是略过取消或一致性处理。调试时先定位最后一个已确认事实：调用有没有进入执行体、实际文件是否改变、最终结果是否已提交。比只看一个红色错误框更有解释力。

14 / LESSON 04
从“可见”到“可执行”，再到“已确认”
能力目录
Definition → 作用域视图 → Schema。它回答模型能表达什么调用。
执行边界
准入 → 守卫 → 能力后端。它回答这一次能实际做什么。
结果证据
规范值 → 内容策略 → 历史。它回答后续模型凭什么继续。
术语本课含义
Canonical value执行端规范 JSON 值，供程序调用；与渲染 content 区分
Guard允许路径之后的单调否决检查
CAS / 版本条件仅在文件版本仍符合观察依据时修改
Exclusive barrier独占调用等待并行池收敛，并阻止后续体越过
PTC通过程序组织工具子调用，外层输出进入模型历史
继续阅读时记住：工具出现、调用获准、环境发生变化、模型获得结果，是四个不同的事实。
